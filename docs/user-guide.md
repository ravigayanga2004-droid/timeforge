# User guide

Administrators begin with Universities, Departments, Academic years, Terms and
Buildings. Add Room features, Rooms and Time periods, then Lecturers, Groups,
Courses and Sections. Sections assign a lecturer, term, enrolled groups, weekly
meeting count, duration, room type/equipment and optional spacing constraints.
Time values in reference forms are minutes after midnight: 09:00 is 540.

Coordinators maintain department courses, sections, people and availability. In
Availability choose a term/resource, select periods, choose an availability type
and apply. Whole-day selection and copying between matching periods on two days
are supported. Unavailable means a hard prohibition; preferred/discouraged means a
weighted preference. Lecturers can edit only their own availability.

Open Timetable Studio, create a timetable for a term and generate alternatives.
Choose count, seed, search budget, optimization and locks; advanced controls limit
sections, rooms or periods. Progress shows the current durable job stage. Cancel
if necessary, or retry a failed/cancelled job. Infeasibility messages identify
candidate-domain problems when possible; a general infeasibility does not claim
to identify a minimal conflicting subset of requirements.

Compare alternatives by penalty, conflicts and utilization. Inspect a version or
make it active. In the calendar, filter by lecturer/room/group/section/day; switch
week/day/list/conflicts. Concurrent independent sessions appear in separate lanes.
Click a session for full details. Drag/drop or the dialog edits time/room. Locks
need an unlocked saved version before movement. Undo/redo works before saving.

The server previews conflicts and suggests validated placements where one move
can fix the whole candidate schedule. Save creates a new version. Conflict drafts
are explicit and remain blocked from submission/publication. Export controls apply
to saved data; save or undo dirty changes before downloading.

Submit a valid active version for review. Administrators approve or reject; notes
are required for rejection and for publishing with soft penalties. Approved versions
can be published. Archive a prior published timetable before publishing another for
the same department/term. New draft edits preserve the existing public snapshot.

Lecturers see assigned published classes; students see their enrolled group's
classes; viewers see published department schedules. These roles cannot modify
versions. Use PDF/CSV/ICS export or Report an issue. Notifications show generation,
review, publication, import and schedule-change events. Users may mark their own
notifications read. Administrators inspect the read-only audit trail.

For CSV data, download a template, validate/preview, resolve row errors and import
the entire valid file. A duplicate unique code blocks that import. Use the planning
guide/privacy screen for in-app guidance and contact your administrator for account
or retention questions.
